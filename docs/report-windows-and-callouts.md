# 报告弹窗、原页问题标注与模型接入（0.7.0）

## 使用

“报告识别信息”和“诊断报告”的标题栏有“弹窗打开”。弹窗可以最大化，筛选、明细切换、列宽和来源页码保持可用；关闭后返回原位置，点击来源页码自动收起弹窗并定位原页。原页区域也可弹窗，适合同时阅读报告和问题引线。

原页下方“问题引线”控制圆点、折线与问题框。问题框在报告旁的专用区域，不覆盖原页数值；问题较多时该区域可以滚动。展开依据和建议后自动重新排布。待核实为橙色，已有记录支持的确认问题为红色；重要程度高或来自模型本身，不会使问题自动确认。文件级问题明确说明圆点不是具体错误单元格；OCR表格块位置也不会冒充逐单元格精确定位。

“导出引线批注副本”生成新的PDF及配套问题清单。PDF增加问题侧栏，原件页面仍在左侧；文字较多时重复原页并标记标注续页。输出清单保存源页／副本页映射。完整问题保留在PDF批注和JSON中，过长的可见文字明确标为摘要。原件字节和原签署证据不修改，副本不宣称重新验证原签名。

旧标准批注和历史导出保持可读，CLI默认仍使用standard。新的网页导出显式选择callouts。

## 模型与绘图的分工

圆点、引线、避让、翻页缩放和PDF输出由程序完成，不需要模型重画证书。问题来自固定审查记录；模型只提出候选问题及依据、建议、页码和位置。系统仍校验实验室、批次、原件摘要、方案目录摘要、提取版本及坐标。

截图中“80℃温度波动超出要求”等文字仅是用户示意，不作为真实不符合证据。没有具体确认方案时，模型不能凭截图或通用印象建立限值；此时只能做基础审查和候选预对照。

## Codex中使用

Codex读取已接入原件、具体方案和固定提取，按certificate-findings.v1或intelligence-result.v1追加带依据、准确原页位置的问题，再生成新诊断。智能体写入agent_candidate，不代填实际核验人或批准结论。

## 从桌面独立使用

现有本地规则和OCR可独立生成基础诊断与图形标注。PaddleOCR-VL-1.6当前负责文字和表格提取，尚未接入通用模型技术诊断API。

现在可用“智能问题接入”：

1. 打开报告，点击“智能问题接入 → 准备当前报告审查包”。固定包含证书、已确认基准（若有）、候选方案目录及结果格式。
2. 由Codex或用户自己的模型服务按该格式返回JSON。页码和bbox均指留存原页；bbox采用显示方向的0至1坐标。只有表级位置时应明确说明精度，不能猜测错误单元格。
3. 在窗口导入JSON。程序校验版本及位置后，将候选问题加入新诊断并绘制引线；原件及旧诊断保留。方案目录改变后，旧模型包不能无提示用于新方案。

此入口不自动向任何外部服务上传文件。桌面自动调用可选择：

| 方式 | 补充配置 | 边界 |
| --- | --- | --- |
| 外部多模态API | 服务地址、模型名、服务端密钥、明确的数据发送范围 | 可看原页、按JSON返回；需实际连通性和结果验证 |
| 本机模型HTTP服务 | 本机服务地址、视觉模型、内存和速度测试 | 资料可留本机；不能把OCR环境存在当作技术诊断已部署 |
| 本地规则＋JSON接入 | 无外部API配置 | 现在即可使用；复杂语义问题需模型或实际核对补充 |

接入自动调用时仍通过独立适配器消费固定审查包，不让HTML直接持有密钥，不把密钥写到实验室业务JSON或导出中。云端发送资料前需明确具体服务商和数据范围。当前未配置API地址、模型名或密钥，因此不显示已连接，也不进行外部调用。

可参考提供视觉理解和结构化输出能力的服务，例如[阿里云视觉理解](https://help.aliyun.com/en/model-studio/vision)和[结构化输出说明](https://help.aliyun.com/en/model-studio/qwen-structured-output)。具体模型及参数应以选定服务商当前文档和联调结果为准。

## 实现与维护

- web/report-panels.js移动同一DOM面板，避免复制ID、控件和第二套数据；关闭、Escape及批次切换均恢复面板。
- web/callouts.js仅根据固定发现和显示尺寸绘图，筛掉其他证书、其他页及已关闭／排除的问题。
- adapters/pdf_callouts.py在新副本增加侧栏，保留已有可见签章外观，记录原页到副本页映射；不覆盖旧导出。
- application/intelligence.py固定候选目录上下文；模型返回不改变方案限值、原件、实际核验和技术批准。
- 浏览器测试覆盖面板复位、来源定位、筛选同步和问题框排布；自动测试覆盖分页、旋转坐标、原件摘要、既有表单外观、过长问题及候选不升级。
