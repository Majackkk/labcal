# 方案编制与报告诊断的职责边界（0.8.0）

本机工作台仍通过桌面入口或 `./labcal open` 使用。两条线路共用实验室、批次及原件引用，不共用可编辑的参数限值。

## 两条线路

```text
设备资料 → 候选方案 → 新方案版本 → 用户明确确认 → 固定验收基准
                                                  ↓ 只读引用
报告原件 → 固定提取 → 报告识别更正 → 诊断快照 → 页面 / Excel / 批注副本
```

- 方案编制：`application/plans.py`、`workbooks.py` 管理候选参数、依据、版本、确认及基准。保存技术变更建立新版本。
- 报告诊断：`report_workspace.py` 组织匹配，`report_diagnosis.py` 固定视图，`point_comparison.py` 将对应状态与技术结论分别映射。
- 报告更正：`report_corrections.py` 只允许报告身份、日期、依据等识别字段；拒绝方案要求、MPE、确认人和技术批准。更正仍为候选，不成为人员核验或设备用途批准。
- 模型只提出候选；审查包绑定报告更正和候选方案摘要。更正后旧模型结果不可直接导入。
- 周期、趋势和异常影响继续预留，本次不启用。

## 固定快照与更新

新诊断保存在 `certificate_reviews.payload.report_views`，随原审查一次写入，不在读取时重写历史。每份报告固定识别字段、设备关联、方案引用、八类诊断、逐点表、技术项目汇总和诊断前提，并保存视图摘要。

页面和导出读取同一视图。原件提取版本、报告更正、关联、方案目录、证据或诊断规则改变时，显示“诊断待更新”。旧快照整体保留，不混入新的识别值或限值；当前工作台要求重新诊断后导出。历史CLI导出仍可按原快照查看。

历史版本没有新快照时，工作台显示更新提示，不将旧问题叠到新识别信息上。旧资料库新增更正表为增量迁移；读取历史任务会先关闭查询游标，再进行后续读取或迁移，避免同进程查询持锁。

## 个人使用界面

1. 导入方案后自动分类；报告导入后留存、识别和匹配。
2. 顶部提示当前诊断前提；未匹配设备时显示“尚未建立对照”，不统计成方案外项目。
3. “更正识别”填写字段值、原页及原因，保存后生成新诊断。无需增加登记核验、补充问题或审查记录模块。
4. 逐点表独立列出对应状态与技术结论。默认五列适应右侧宽度，保留完整列、列宽拖动、区域分隔及弹窗。主界面与弹窗分别保存列宽，避免放大后的宽度挤压主界面。
5. 默认原页只显示定位点，保护报告大小；展开原页弹窗显示完整引线和问题框。系统诊断前提、缺少机构资料等不在原页画错误点。
6. 点击“导出完整诊断”，在弹窗下载摘要、全部逐点对照和批注。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| 尚未开展 | 设备或确认方案等前提未齐，不代表项目不合格 |
| 待核对 | 有识别线索或歧义，仍需原页或交叉证据 |
| 缺少资料 | 缺少具体输入，诊断维度列明下一步 |
| 需专项核对 | 当前通用规则不支持复杂工况、公式或语义适用性 |
| 符合／不符合 | 来自确认方案和已核对结果的实际判定，附计算记录 |
| 不适用 | 方案采用其他实施方式等明确适用边界 |

点位相同、OCR置信度高、模型提出疑点或程序测试通过，均不会直接产生技术批准。参数覆盖与单点结果分别判断，缺少其他点不会把已取得证据的单点计算改为另一数值。

## 信息与输出

八类诊断包括身份与准确性、报告完整性、参数覆盖、数值一致性、不确定度、方法适用性、机构及溯源、结果与用途要求。可识别的跨页编号、页码／总页数和日期顺序有自动一致性检查；疑点保持候选并保留原页。方法语义、复杂CMC、误差定义及不确定度适用范围不能靠字段存在判定通过。

自动OCR对有文字层但页眉是图像的PDF增加局部Tesseract补识别，保留原有文字。页眉补识别可能有错字，仍可在识别区更正；不宣称OCR正确性已核验。手动Paddle模式和扫描页的现有路径保持可用。

完整诊断包：

- `diagnosis.html`：八类摘要及全部逐点对照。
- `comparison.xlsx`：诊断摘要、逐点对照、固定输入。离线标准库适配器输出，无公式或宏，保留十进制原文。
- `comparison.csv`：与逐点表同一行集，对公式前缀做文本保护。
- `diagnosis.json`：固定视图及其引用，不是第二份可编辑方案。
- `issues.md`、`summary.md`：内容疑点与诊断前提分别列示。
- 原页批注PDF：仅有具体位置的内容疑点绘制引线，原件不变。

现有 `review.json`、历史HTML及旧导出继续保留。复核处理不改写原计算；新证据需生成新诊断。

## 数据契约与验证

- 新增 `report-field-correction.v1`、`report-diagnosis.v1` 和 `point-matrix.v2`；v1逐点契约继续保留。
- SQLite新增 `report_corrections`，按实验室库内的批次和提取版本追加。事件、摘要、备份及完整性审计包含更正记录。
- 隔离测试验证双向不改写、跨实验室／批次隔离、旧库升级、旧快照保留、模型包失效、逐点真实判定及完整导出一致性。
- 模拟确认仅在临时测试实验室；实际方案继续保持候选，未生成真实确认或验收基准。
