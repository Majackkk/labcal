# 实验室检定校准结果确认表

每个实验室选用自己的Word模板。用户要求对某台设备进行“校准确认”“检定确认”或“填写确认表”时，完成证书自身及实际检测用途分析，并填写该实验室的选定模板。单纯讨论某个技术问题不自动生成确认表。该流程不代替方案确认，不扩展周期、趋势或异常影响模块。

2026-11-10起，先读取本实验室business context，prepare以明确equipment_key固定用途和配置；coverage条目use_ids保留每个已知用途的处理去向。analyze、format及finish继续共用既有技术检查，并核对任务准备后的相关上下文变化。适用批注PDF及其原件/任务清单在finish经--annotations、--annotation-manifest共同登记；交付manifest包含Word、结果及上下文，不另建判据来源。变更复核、显式证书替代和问题跟进见[当前工作流程](workflow.md)。历史确认不追写。

## 验收依据与器具参考的边界（2026-11-09）

检测方法和校准规范/检定规程同时查阅，分别落实作用。计量确认目标是实际预期用途适用，不是将所有查到的器具限值并列成强制门槛。依据：CNAS-CL01-G002:2021第4.9条（预期使用要求、修正及项目U重新评定需要）及CNAS-CL01-G001:2024第6.4.4条注2（实验室根据校准结果判断适用性）。2026-11-09复核CNAS官方正文：[G002](https://www.cnas.org.cn/cms_files/filemanager/328304128/attach/202412/EE1ABB819EAE436B209D6003663618B7.pdf)、[G001](https://www.cnas.org.cn/cms_files/filemanager/328304128/attach/20248/1719986730330001257.pdf)。

先确定要求性质，再比较，沿用technical_review、五列附页和三维色系：

1. **适用验收要求**：方法明文、方法明确引用的器具要求、实验室已有依据的验收要求及实际适用的强制要求。写明来源、条款、测量量和条件；不把器具参考升级为实验室已批准准则。
2. **器具技术参考**：写明等级配置、限值、载荷及选用理由，区分首次检定、后续检定或使用中检查参考。不因已在用自动选最宽限值。比较仅支持所列器具项目，不等于按该规程检定合格，不代替用途判断。
3. **特性记录**：确无适用独立判限的已有特性保留原值，不伪造合格或制造缺口。

冲突处理：方法要求不满足，即使器具指标符合也不能确认该用途。方法满足、仅器具参考不满足时，记录真实比较并评估故障、稳定性及用途影响，不自动否定用途，也不能忽略异常。方法明确引用、实验室实际采用或强制适用的器具要求未满足，不得绕开后宣称全部要求满足。正式检定不合格不得由用途确认覆盖。校准程序/条件缺陷影响数据有效性时先处理证书可靠性，与某参考等级未满足分别处理。

U跟随各自要求：有方法误差限，按该限及选定规则评价；只有分度/读数要求，不将其当MPE或U上限。器具U/MPEV在紫色参考段独立计算、判断，不在同一句接出用途合格。证书U只是检测项目U的输入之一，不能当成密度或灰分最终结果U。

第一页注明“主要依据：检测方法；校准依据：证书所列规范；器具参考：具体规程及项目”，避免仅并列勾选。附页分列【方法要求／比较／用途判断】和【器具参考／比较／参考判断】；U栏分【用途U评价】及【器具参考U评价】，MPEV写出具体值及载荷，不只写“见表3注”。方法未给独立绝对误差或U限值，不额外宣称该绝对准确度合格。总体结论限定为设备已校参数及明确用途，不扩大为检测方法全过程或最终结果U验证通过。

新任务`basis_role_version=1`；规则增加`basis_role`（acceptance_requirement / technical_reference / characteristic_record）及`basis_scope_quote`（正式表说明作用的摘录）。器具指标成为验收要求时用已有`applicability_basis`记录采用依据。参考未满足或证据不足时增加`reference_impact_quote`，摘录正式表中对用途影响的评价。analyze、format、finish共用检查；旧任务兼容，历史不改写。只检查声明及引用，适用性仍由技术审查判断。不增加第二份限值库，不读写校准方案。

```sh

./labcal document-template show --lab LAB_ID --role calibration-confirmation
./labcal confirmation prepare --lab LAB_ID --campaign CAM_ID --extraction EXT_ID --equipment 设备名称及编号
```

模板原件按实验室接入objects，查阅副本保存在`templates/calibration-confirmation/SRC_ID/`。meta保存不可覆盖的版本记录及当前选用指针，模板目录保存对应TPL_ID.json。新版本追加保存，旧版本可按标识读取；模板跨年度复用，各批次固定引用模板原件。模板选择是用户选用表式的证据，不是技术批准。

prepare固定模板版本、报告提取版本、原件摘要及实验室批次，保存到`processing/certificates/CONF_ID/confirmation-task.json`。它不生成已填写表或作技术结论；聊天智能体先完成分析记录并执行`confirmation analyze`，无阻断后再调用文档技能复制原模板填写。无模板、未归入批次或摘要不符时明确缺口。

## 填写和交付

1. 原证书、检测方法、用途条件和机构能力分析引用现有诊断结果。设备名称、编号、校准日期、标准器及证书编号按实际原页填写；部门、周期、现场/送校、实际外观检查等缺证据时留空，不从模板预设选项推断事实。
2. 附页按参数、工况、范围/点位分行填写，保留五列：参数/范围及来源、方法要求及判断、U及评价、溯源资料、修正及应用。U仅用于其适用项目，不复制到未给出U的项目。规则和“精确至”保持原文意义。
3. 主表技术项目按证据填写；无法确认不强选是/否，应说明本次评价范围及其限制，缺少关键依据时先解决缺口。模板已有“满足要求”“可以使用”等文字只是选项标签。确认人、设备管理员、技术负责人签字及其日期留空，不代填批准意见。最终表不使用“待补”“待确认”等过程用语，不能以措辞清理掩盖证据缺失。周期调整、降级使用和实施修正需要相应直接依据。
4. 保留模板原件字节。使用文档技能读取实验室模板填写指南，创建工作副本和artifact.md，保留表号、主表及附页结构、表格、复选框、页眉页脚和注释，按必要内容扩展页数；长内容用原表行样式扩展，不重建成通用空白文档。
5. 每次填写建立新的CONF任务，处理稿在任务目录；完成的Word按模板风格另存到`outputs/certificates/CONF_ID/`，名称含设备标识。同时保存来源摘要、模板版本、对应诊断及实际填写范围的JSON清单。原件和旧记录不覆盖，年度批次由任务引用确定。
6. 按文档技能渲染最终Word并核对每页，解决字体、溢出和跨页问题后交付。正文填写不代表实际人员已签署。同步更新实验室诊断Excel；Word为单台设备确认记录，Excel为跨设备汇总，均引用相同诊断依据。

代码使用通用模板角色，不硬编码实验室名称、表号或器具；个别表式的字段定位及签字栏规则放在对应实验室模板目录的填写指南中。

## 用途分工与最终交付（升级）

确认顺序固定为：证书自身检查 → 本实验室采用方法及实际用途 → 核清要求含义、比较量和规则 → confirmation analyze → Word及原页批注 → 渲染复查 → finish及Excel。方法采用、潜在用途建议、用户确认的设备分工分别记录。所有相关方法应检索设备章节、试样尺寸、操作步骤、图表和注释；未拆解内容不能称为无要求。共享标准库不写实验室设备分工。

按外量、内量、测深或相应功能分项。区分精确至、分辨力、MPE、试样尺寸公差和U；不默认半个末位、三分之一或保护带为通用规则。工作点未与校准点重合时，结合选点方式、校准范围、实际使用和必要核查评价，既不自动否定用途，也不以少量点位证明所有尺寸。测头、接触方式和测量基准纳入适用条件。标准要求与补充建议分开。

最后五列由一份`confirmation-record.v1`记录生成：参数及来源、方法判断、U评价、溯源资料、修正及应用；每行增加功能、测量任务和技术状态。状态为满足要求、不满足要求、证据不足、未承担该用途；不代填人员使用批准。表格保留结论、必要比较和判断规则，重复推导放处理目录。签署栏及无据管理字段留空。

```sh
./labcal confirmation finish --lab LAB --campaign CAM --task CONF_ID --record result.json --document filled.docx --appendix-table 1
```

先用文档技能完成渲染和全部页面核对，再finish。表格索引从0开始，按该实验室模板实际指定。程序逐单元格比较Word附页与记录，核对任务/模板/证书摘要，固定交付文件摘要并登记；重复提交可复用，改变内容需新任务。默认同步实验室Excel中的“设备确认记录”页；摘要异常停止汇总。主表与其他方法诊断页保留各自范围，不能把此确认记录解释成校准方案批准。纯技术讨论不自动发布确认表。

## 用途覆盖发布检查

`confirmation prepare`自动固定本实验室当前采用的全部方法原件。另以`--context-sources REF_ID ...`纳入本次讨论/已发现的关联标准；同设备名称标识已发布记录中的关联范围会自动延续为参考检索范围，不升级为实验室采用。不同实验室不混用；后续标准换版要重新建任务。

提交记录的coverage逐标准列出检索范围、尺寸任务、处理去向、理由、确认表行号和原页证据。每项去向为本设备评价、其他量具承担、本次不适用、证据不足。漏掉固定范围中的标准、没有行去向、原页摘要不一致均停止发布；证据不足时不得声明完整符合，但不能自动据此限制设备使用。每个标准内还有多少未发现任务仍依赖原页分析，程序不能证明条款语义无遗漏；scope_note必须说明实际检索范围。

Excel增加“用途覆盖清单”，与设备确认行引用同一记录。旧版表标识“未进行用途覆盖检查”，不追写历史原件或伪造完成状态。最终Word保留具体使用边界，不出现过程占位语；不为页数删去标准要求。


## 供审核专家查验的附页表述

用户明确后续计量结果确认附页直接供审核专家查验。正式附页写明适用任务、标准号及版本和条款、实际校准结果、不确定度及必要评价、溯源引用、符合性结论、修正方式与使用限制。已确认的实际用途全部保留，按功能及任务分项；以简洁、直接、可复查的表述呈现。

### 结果结构与阅读层次（2026-11-05）

用户选择参照所提供附页图示的信息结构，不采用其技术结论或判定规则。后续保持实验室五列表式，以原证书的项目、工况或点位为基本分组：同一工况下的多个特性量完整列在该行，避免将不同温度/负荷的同类结果汇总成大段文字后再要求读者交叉对应。外观等定性项目单列；按证书结构和实际数据选择行数，不硬编码温度、设备或客户。

- 首列采用加粗项目/工况标题，按固定顺序逐条列出该组校准结果、单位、正负号及来源页码；同组结果不拆散到多个功能行。U重复列示时须明确其适用测量量。
- 方法列按校准依据、检测方法要求、结果比较、判断分段；只有适用的内容才列示，不机械增加没有数值要求的“合格”判断。
- U列按U及k、影响评价分段；溯源列按机构、标准器及证书分段。相关资料可明确引用同表具体工况行，不使用跨页无指向的“同上”。
- 外框与纵向列线清晰，工况行之间及单元格内不同主题之间可用真实灰色虚线边框分隔，不输入连续减号充当边框。标签加粗，正文顶端对齐，表头跨页重复，同工况结果尽量整行保留。
- 结构优化不新增证书外参数、不复用示例数值，不默认图示中的三分之一比例、保护带或第三方结论正确；技术判断仍以原页及独立适用依据形成。

- 方法列采用“标准及条款 → 对应要求 → 实际结果比较 → 明确结论”。只在证据支持的范围内写“满足某任务的精度要求”，不能用措辞优化扩大确认范围。
- 删去对话式解释、自我说明和反复辨析，例如“本表不以……直接认定”“此为……不是……”等；具体测量方式、适用条件或判定规则如影响结论，仍须简明保留，详细推导放处理记录。
- 同一报告编号、误差、U及溯源资料可集中列示，后续明确引用所在行或证据编号；不能跨功能借用U、将某点修正量外推全量程，或在无依据时套用“不需修正、直接读数”。
- 已明确的方法采用和实际设备任务列入正式适用结论。仅供参考、实际分工未明确的用途保留在覆盖清单和分析记录，不能与正式用途混排成已确认适用。未纳入本次确认的参考任务仍须记录理由及证据缺口，不得删去覆盖记录来伪造完整性。
- 其他量具承担的任务及本设备使用限制集中说明，避免多行重复。证据不足明确具体未能判断的项目；使用限制另须有技术依据，不写“待补”“待确认”等过程占位语，不代填实际人员批准。
- 正式表不可仅写“详见系统”。依赖用途覆盖清单或详细评价作为判断依据时，将其作为有明确编号、版本及对应关系的配套记录一并交付；独立阅读附页也应能理解核心判断。
- 交付前同时检查：实际用途覆盖完整、主附表及Word/Excel一致、标准引用可定位、结论有依据、限制可执行、无过程措辞、无重复堆砌、人员栏未代填，最后逐页核对版式。不为页数删去技术要求。

本规则适用于后续生成或明确要求修订的确认记录；不追改已归档的原件与历史输出。


## 判断链与选择项（2026-11工作流升级）

本次升级沿用prepare → 分析 → Word → finish → 实验室Excel，不新增审批流，不改方案编制及方案履约比较。适用于新发布和修订的确认表；既有输出不追写。

### 分析与正式文字

1. **分用途命名。** 每行首列写明function和purpose的原文名称，例如“外量爪：试样宽度测量”；实际点位/范围、误差及证书允差比较在同列列出。没有适用允差或不承担该用途时说明理由，不补造限值。
2. **分开两种符合性。** 器具符合证书所列允差，不自动等于满足检测方法；方法列逐项保留标准版本、条款、要求、结果比较和结论。同一用途可合并多标准，但各要求与结论必须对应。只核对了证书允差时明确其来源，不能写成已独立核验规程全部要求。
3. **规则明确、计算适量。** 方法列说明判定规则及依据；U列保留该项目U、k、适用范围和必要的比较/计算。没有数值判据时说明如何评价及其范围，不能制造数值限值。保护带是所采用规则时说明性质；不默认半个末位、1/3或|e|+U普遍适用。精确至、分辨力、MPE、尺寸公差分别使用。对临界值给出可执行处理；需要数值复核区间时，从有依据的规则推导，不凭经验给区间。
   需要采用JJF 1094时，必须执行[U与误差限分情况评价](uncertainty-decision-rules.md)：先区分第5.3.1.5条检定规程分支与第5.3.1.4/5.3.1.6条一般分支；U列写明适用条款、MPEV来源、必要的U/MPEV比较、后续数值判据及结论。超过1/3不能止于“比例不满足”，须完成合格/不合格/待定区评价；不自动改写实验室已采用的其他有据规则。
4. **能力与现场条件分开。** 先评价仪器能否达到所讨论用途的范围和测量要求，再说明测头、接触线、测量基准、装夹等必要条件。仅缺现场观察资料不自动否定能力；若缺失条件会改变判断，明确限定结论。不能以一个点零误差证明整个区间线性，也不能因校准点未逐一重合工作点就直接否定用途。
5. **区分用途身份。** 正式实际用途和“在指定条件下的能力评价”明确标识；后者不代表实际设备分工已被确认。仅供参考的标准保留覆盖记录，不伪称实验室已经采用；也不以“非已采用”为由抹掉已讨论用途的能力分析。
6. **正文可独立查验。** 正式表保留足以理解结论的分析，不能只写“结合误差和U评价，满足要求”或“临界复核”。内部覆盖清单不强制印在表内；当正文已经自足，可删除“配套记录”说明，清理悬空引用。确实依赖外部资料的判断仍需明确编号/版本。

程序检查只验证方法关联、声明类型和一致性，不能代替语义核实。执行智能体仍逐条回看方法原页，判断要求涵义、实际测量量、U的用途影响及总体结论范围。仅能确认分度/读数能力时，正式文字应限定范围，不写整项检测用途全部满足；关键依据不足时先解决判断依据，明确尚不能判断的项目；限定评价范围不等于限制设备使用，不通过改写措辞掩盖。新增规则不改方案编制及方案确认线路，旧输出留存。


## 技术判断先于正式填表（2026-11-07）

此节修正早期“证据不足只能限定范围”的处理方式。评价范围是本次分析覆盖的对象；设备使用限制是对操作的约束，两者不互相推导。仍使用原prepare、五列记录、format、finish与实验室Excel；只增加一个无业务写入的分析入口，不增加审批层级、数据库或另一套限值来源。

### 执行智能体的技术分析

1. 固定实际用途和用户给出的评价范围，先检索所采用检测方法的相关设备、步骤、图表、计算、注释及引用。方法用途要求、独立器具要求及适用的法定要求分别满足；不得用“方法优先”取消其他适用要求，也不得用器具合格替代用途合格。
2. 保留要求原文并解释关键术语。“精确到”、感量、分度值、误差限、准确度和不确定度不互换。解释有歧义时回看上下文、引用标准及必要的权威资料；来源不能支持解释时，保存具体争议并及时与用户沟通，先解决再填写最终表。不能为了方便判定选择一种含义，也不能将未知含义登记为“没有要求”。
3. 将要求量和实测量对齐：名称、误差定义、量纲、统计量、工况、点位/区间及修正状态相符。需要换算时保留来源和推导，不默认标准偏差等于极差；分度符合不推出绝对误差符合。
4. 验收要求与判定规则分开核对。只有要求明确后才能选直接比较或其他规则，逐规则引用实际依据。JJG的首次检定/使用中限值不自动成为用途MPE；未约定的保护带不成为否定用途的依据。直接比较时U另列评价，不因补充的含U区间跨界而改写直接比较结论。
5. 逐项反向核对：如果去掉器具等级判断，方法用途结论是否仍有依据；如果去掉U附加计算，是否仍执行用户选择的规则；所写使用限制是否确实对应一个已证明的不满足项。用统一单位复算界限点、最大值、零点及例外项。程序只检查声明一致性，不能替执行智能体完成这些计量判断。
6. 技术问题解决后才形成正式五列文字。未能判断、不满足、中性特性分别记录；“全部用途满足”须有各实际用途支持。真实使用限制写明对象、范围与操作方式。签名、批准及无依据的周期继续留空。

### 分析入口和共享检查

```sh
./labcal confirmation analyze --lab LAB --campaign CAM --task CONF_ID --record result.json
```

该命令在没有Word的情况下检查固定输入、证书自身、项目/方法覆盖、要求类型、逐项依据和总体结论，返回`ready_for_document`和具体`issues`。不登记确认、不刷新Excel、不写入方案。`semantic_verification=false`和`technical_approval=false`明确其不是原文含义核验或人员批准。旧记录可用该入口评估修订前缺口，不改写旧任务。

新prepare固定`reasoning_version=1`。已有`technical_review.rules`每条增加`reasoning`：

| 字段 | 内容 |
| --- | --- |
| requirement_status | established / unresolved / no_independent_limit；依据是否明确，与结论符合性分开 |
| interpretation_status | unambiguous / resolved / unresolved；weighing_precision须为resolved |
| interpretation_evidence | 原文上下文、引用及解释依据；已有source_reference/method_links定位原件，不复制新限值 |
| quantity_match、quantity_basis | direct / derived / not_comparable，及测量量定义/单位/统计量/工况对应或换算依据 |
| decision_evidence | 本规则的适用依据，不能只写“符合JJG”或“足够小” |
| uncertainty_role | separate_evaluation / decision_component / not_applicable，与实际规则和U列一致 |

未核清的要求/术语阻断正式生成。format与finish重新调用同一`review_confirmation`，记录更改后必须重新核对；不通过一个可过期的“已审核”标记放行。旧归档继续读取，修订另建任务。

总体选择`limited_use`时，`technical_review.use_restrictions`逐项包含`rule_numbers`（从1开始）、`scope`、`reason`及`application_quotes`。每项必须关联intended_use且does_not_meet的具体规则，引用相应行application中的实际限制文字，并有仍满足的用途。仅有证据不足、器具分项结果或用户指定仅评已校点不能生成使用限制；如实保留尚不能判断的状态，不能用限制措辞结束技术分析。

### 架构与文件归属

- `domain/confirmation_reasoning.py`：纯判断关系与状态一致性，无文件、数据库或客户参数。
- `application/document_templates.py`：统一固定输入和共享检查，analyze/format/finish复用；`confirmation_quality.py`继续负责证书与方法来源关联。
- `domain/document_template_contracts.py`为唯一契约，`./labcal schema`生成交换结构。
- 处理记录仍在所属实验室`processing/certificates/CONF_ID/`；正式Word/结果仍在`outputs/certificates/CONF_ID/`，每实验室Excel按原方式投影。方案编制、方案基准、HTML及原件适配层均不消费新结论修改限值。


## 原件独立重新确认

用户要求排除历史结论时，使用`confirmation prepare --fresh-review`。该入口保留当前实验室明确采用的方法标准和本次显式指定的标准原件，但不读取历史确认表及其衍生关联范围。实际用途只使用直接用户证据，另存本轮来源记录。历史原件和输出不删除、不覆盖；新任务仍执行相同的原页、技术判断、用途覆盖及发布检查。
