# 数据模型与判定边界

数据库是业务事实的在用来源；JSON是交换格式及固定快照；Markdown与HTML是呈现输出。程序契约位于 `src/labcal/domain/contracts.py`，通过 `./labcal schema` 生成 `schemas` 中的文件。

## 年度批次与候选资料

`campaigns`保存实验室内的年度、名称、工作状态和记录摘要；`campaign_links`按资料类别、稳定标识及修订号保存固定摘要。年度允许待定，同年允许多个批次；年度标签不改变校准活动日期。修改元数据需当前摘要，归档后禁止追加。

`workbook_imports`保存工作表、原始单元格、公式及缓存、合并、列映射和候选行。设备分组不自动变为实际资产。读取时自动生成候选设备目录，保留工作簿版本、参数行号和原文锚点；技术就绪和确认仍沿用原规则。

`workbook-extraction.v2`为七列候选增加固定`fields`及逐字段`field_sources`。七个值分别为设备名称、厂家、型号、编号、参数、MPE和不确定度原文，缺失为`null`，界面显示`-`。程序不从候选文字生成可执行限值，也不把序号当作设备编号。v1快照保留原摘要，读取时另外生成`candidate_view`供新版界面使用，不回写原payload。导入文件夹的只读原件及提取记录是可校验的留存副本，数据库仍管理在用事实。

`intelligence_packets`保存固定上下文与结果契约；`intelligence_results`单独保存模型候选字段和结果。只有实际人员核验入口可写入`certificate_evidence`。问题候选继续通过`certificate_findings`接入，不能由模型声明已证实。年度批次索引是数据库投影，不能作为另一个可编辑事实源。

实验室设置变更需明确操作人、选择说明和期望摘要，元数据保存单调设置版本，事件保留前后内容。实际资料归属、确认记录和基准不因显示名称变化而替换。

## 方案参数

每项要求有独立标识，保存参数名称、被测量、组件、通道、模式、单位、范围、点位、工况、报告字段、限值、不确定度要求、规则和证据。

`delivery_route` 分为 `external_calibration`、`legal_verification`、`internal_calibration`、`functional_check`、`pre_use_check` 和 `unresolved`。正式外部证书组仅收集前两类，其他要求仍保留在基准中。

`coverage_policy` 分为逐点、范围、代表性点位及未明确。范围和点位采用十进制字符串；浮点数、非有限数、反向区间和越界点位不会成为有效输入。

已有Markdown方案只提取原文行和候选参数，保留原始列值。它们的单位、实施方式、点位和规则在完成结构整理与核验前保持未明确，不从字符串直接推定合格判据。

## 三种独立状态

1. `user_confirmed`：是否保存针对该具体版本的直接用户确认。
2. `coverage_ready`：参数、对象、单位、范围／点位、报告要求及相应证据是否足以核对覆盖。
3. `decision_ready`：是否另外具备完整的逐参数限值和可执行规则。

未确认不能编译正式基准。覆盖已就绪而规则未明确的参数，可以核对项目覆盖，不自动判断设备满足用途。

## 证据

来源分为规范、制造商资料、实验室要求和历史方案。历史方案证据不能自动成为已核验事实。规范及制造商主张需要与方案版本、参数摘要、原件摘要、页码／锚点、实际核验字段和核验记录绑定。

原页核验记录是人员提供的本地审核记录，不是程序已经证明条款语义正确或完成身份认证。用户确认实验室要求，也不等于确认规范原文数值正确。

## 规则

当前支持区间、单侧上限、单侧下限、明确保护带和定性规则。规则必须指定比较输入；保护带必须另指定不确定度输入。限值可以明确包含或不包含边界。

输入与限值按相同量纲换算。百分比需明确读数、参考值或满量程基准，不同基准不能直接比较。数值使用Decimal；程序不执行任意公式、代码或尚未支持的规则字段。

第二阶段可接入证书文字、表格和OCR候选内容；经实际核验的结果再进入规则比较。不执行复杂不确定度评定、任意公式或未明确的CMC计算。

## 证书与问题

提取保存原件摘要、解析器版本、页码、文本行、候选字段和表格。位置为旋转后可见页面上的比例矩形 `[x0,y0,x1,y1]`，取值0至1，并可绑定原文行标识；视觉位置不假造文字行。

`certificate-evidence.v1`逐字段／结果记录实际核验人、时间及位置。声明字段缺失或结果录入完整需核对全部页面。结果的`inputs`名称与方案的`decision_rule.input`对应；`reported_fields`使用报告字段名，例如示值误差可报告为`indication_error`，而方案约定的比较输入可能名为`error`。不推断任意字段等价或公式含义。

`certificate-findings.v1`接入操作人员或智能体提出的补充问题。其重要程度与证实状态分别管理；原件及依据摘要检查通过不等于问题已证实。实际复核通过`finding-resolution.v1`记录，原始审查轴状态仍保留；补证后重新审查。

审查快照保存基准摘要、证书提取摘要、核验记录标识、规则版本、三项状态与逐问题位置。证书资料、方案覆盖、用途判定分别呈现；无基准时后两项保持待核实。没有匹配到参数时，只有完整的实际结果核验记录才支持确认缺项；尚未录入的结果不能当作证书缺项。

`institution-evidence.v1`绑定范围附件原件及核验记录。范围按活动日期核对，不能将当前范围自动用于历史证书。其他溯源路线及CMC公式未充分核对时保持待核实。


设备对应关系核验同时保存当时的配置摘要；设备配置改变后，旧证书核验关系不自动用于新基准。

## 报告接入与设备关联（0.4）

`report_jobs`记录实验室内某批次的后台进度，状态为queued/running/completed/failed/interrupted。阶段、实际页码、总页数、原件标识和错误分别记录；进度不是技术事实。服务重启将未完成任务标为中断，不显示虚假扫描。并行处理最多2份，待处理队列最多50份；文件独立提交，一份失败不回滚其他文件。

`report_associations`追加保存设备关联快照及摘要，绑定实验室、批次、证书提取摘要、候选目录摘要、识别器版本、匹配理由和候选设备固定引用。状态分别是matched（唯一身份关联）、suggested（名称候选归类）、ambiguous、conflict、unmatched及operator_linked（操作人明确资料归属）。所有状态均不构成技术批准或实际设备核验。人工选择需当前关联标识、实际操作人和依据；自动重匹配不覆盖人工选择。

方案中的缺失厂家、型号和编号保持空值；标题中的装饰文字和型号样式仅可辅助名称检索，不写入明确身份字段。相同名称及型号无法区分多台实物时保留歧义；不同标识之间不通过数值化忽略前导零。受校设备身份优先读取首次提供该字段的页面，并排除已识别标准器区域，标准器表格仍保存在原提取中。所有字段仍为候选。

报告原件归档在批次`证书报告/原件档案/SRC_ID/`；按关联结果在`设备关联`、`待确认关联`或`待匹配`下追加索引，索引引用统一只读原件。旧关联目录是历史记录，不能直接作为当前分配清单；当前关联由数据库最新快照决定。年度调整移动完整批次目录，原件摘要与技术版本不变。

六类诊断为固定审查的只读投影：信息完整性与一致性、溯源性、实施依据及标准适用性、参数覆盖性、结果符合性、不确定度适用性。显示六类卡片不表示六类专业评价均已自动实现；溯源链、标准适用性及不确定度适用性缺少原页与外部依据时保持待核实。历史任务读取自己的固定审查数据，不套用新任务结论。


## 个人工作台双列对照（0.4.1）

`report-comparison.v1`是只读投影契约，含实验室／批次、证书提取摘要、方案基准或候选工作簿摘要、固定任务标识及逐项双列内容。每行保存方案文本、证书文本与跨报告原页锚点、结论、文字关联信号、理由和原表位置；投影本身有内容摘要，不生成可编辑限值副本。`candidate_preview`、`confirmed_baseline`与`unmatched`分别标明预对照、正式基准和未匹配状态。

候选文字一致或相似不自动将status写为passed；不同候选值也不自动写为已证实failed。正式参数结论来自所引用固定基准的既有比较结果，并保留对应组件、工况和点位。个人界面删除人工登记与历史列表，不删除原件或技术版本，也不补造真实人员证据。
