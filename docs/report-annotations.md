# 校准／检定报告批改副本

2026-11-07用户选定B3紧凑字段卡。拟替换或删除内容使用左下到右上的斜线，不用横向删除线。此为导出规则，不改变测量值、技术限值、问题确定性或人员批准状态。

## 共用出口和独立业务线路

聊天式证书自身诊断的`self-diagnosis finish`、检测方法用途诊断的`method-diagnosis finish`、方案符合性审查的`review export`共用`adapters/pdf_callouts.py`的B3输出器（`style=callouts`，渲染版本`b3-uncertainty-basis-4`）。各自任务、证据和判定保持独立，不改方案编制程序或验收规则；确认Word沿用五列表式并共用三维色系。

`review export --annotation-style standard`保留旧边框批注兼容入口。历史PDF不重新生成、不覆盖。重导出使用新输出版本。

## 呈现规则

左侧原页保持原尺寸、原文字与可见签章；右侧新增批注栏。卡片标题保留问题编号、题目、确定性和操作；字段依次为：

1. 修改建议：拟替换／删除为红色，补充／澄清为蓝色。保留适用条件，不预设实测合格值。
2. 核实要求：棕色，写明机构需要核对的内容或处理条件。
3. 原因：紫色标签，正文包含问题原因与依据，放在框内下部。

引线起点为实心圆点，整颗圆点放在原文外的留白处，与原文留出至少4pt间距，并检查邻近文字、扫描图像笔画和表格线；附近无合适留白时退到新增批注栏边缘，不挤占原文。折线不闭合成跨越原文的多余斜线。只有拟替换／删除画斜线；证书真实数值超限不等于文字应被删除。补充／澄清／提示只定位。多卡续页展示对应原页；长原因分段保留，不静默截断。导出清单保存原页映射与渲染版本，PDF批注保留全文。

## 可选批改意图

`self-diagnosis-record.v1`、`method-diagnosis-record.v1`的`evidence`，以及`certificate-findings.v1`的`location`允许可选`markup`：

```json
{
  "page": 4,
  "bbox": [0.52, 0.26, 0.56, 0.28],
  "quote": "原文中的具体数字或文字",
  "origin": "visual_page_read",
  "image_sha256": "实际原页图摘要",
  "markup": {
    "action": "replace",
    "condition": "请先核对误差定义及原始记录，再更正。"
  }
}
```

示例只说明结构；位置、原文与摘要必须使用真实证据。`action`取`replace`（拟替换）、`delete`（拟删除）、`insert`（补充）、`clarify`（澄清）、`flag`（定位提示）。省略时按`flag`兼容旧记录，不从建议文字猜测删除。一个区域对应一个操作；多个数字分别定位。缺项不能虚构原文位置。

替换／删除必须带具体原文，不接受文件级、章节级目标。文字层可用时按指定区域内原文精确定位；不符则报错。扫描件按已回看的小区域画斜线，过大的整表或段落框不作删除目标。OCR候选不升级为已核验事实，扫描图仍须遵守原页阅读证据规则。

## 文件归属和职责

- 通用操作契约：`domain/report_markup.py`；PDF实现：`adapters/pdf_callouts.py`。领域层不加载PDF库。
- 交换结构：`schemas/`，由`./labcal schema`生成；不新建第二套技术限值来源。
- 原件：各实验室`objects/`，不写回。
- 任务和证据：各实验室`processing/certificates/TASK_ID/`。
- 业务输出：各实验室`outputs/certificates/RUN_ID/`，沿用既有登记、摘要与追加保存机制。
- 样式预览和工程验收样张与正式业务RUN分开留存，不当作真实设备通过确认的证据。

## 三个判断维度的固定色系

- 蓝色 `#2363A3`：`certificate_self`，证书自身的信息、计算、表达及结论一致性。
- 紫色 `#7550A0`：`instrument_requirement`，已校项目与适用器具技术要求的比较。
- 橙色 `#A85512`：`intended_use`，已有项目对检测方法及实际用途的评价。

颜色表示判断维度，不表示严重程度、是否合格或问题确定性。卡片标题、圆点、引线和斜线用维度色，并保留文字标签及状态。B3框内“修改建议／核实要求／原因”标签仍采用原定的字段分色，正文深色。斜线只按明确replace/delete意图绘制。

自身诊断出口固定为蓝色；方法用途诊断出口固定为橙色，不能被输入markup改色。器具技术要求通过证据markup.dimension明确声明。没有归类的历史／方案履约比较显示灰色“未分类／方案对照”，不猜成检测用途，也不改变原方案规则。样例：`"markup": {"action": "flag", "dimension": "instrument_requirement"}`。

每条批注只对应一个维度；同一位置存在不同维度的问题则分别说明。没有定位的问题保留在诊断记录，不能捏造删除目标。无未解决定位问题时不生成空的批改PDF。原件及旧副本保持不变。


## 不确定度批注的条款依据（2026-11-08）

涉及U评定/表示、U适用范围、误差与U的比较、判定规则或CMC的问题，执行智能体必须在对应位置markup显式标注topic=uncertainty，并填写uncertainty_basis。只报文件名称或“U过大”不足以成为批改依据。一般问题保留旧格式，不从关键词猜测批注主题或判定规则。

沿用B3三字段，在“原因”框内下部显示：文件全称及编号版本、具体条款/表/附录、支撑本次判断的关键原文、原件/官方来源、有效性核查日期、适用性质及本次应用。全文同时进入PDF批注注释；长内容按原机制续页，不截断。条款原文与执行智能体的推导分开，不能把推导写成标准原文。日期仅为执行智能体的资料核查时间，不代填人员批准。

```json
{
  "action": "clarify",
  "topic": "uncertainty",
  "uncertainty_basis": {
    "role": "supplementary_check",
    "references": [{
      "document": "文件编号及版本《文件全称》",
      "clause": "第X条或表X、注X",
      "quote": "已核对原页的必要原文摘录",
      "source": "已接入原件ID及页码，或官方原文/有效性清单地址",
      "status": "valid",
      "checked_on": "2026-11-08"
    }],
    "application": "说明所引条款如何用于本次参数、范围、E/U与限值的比较及结论；标明必要假设。"
  }
}
```

role为requirement（适用要求）、guidance（技术参考）、supplementary_check（补充核查）。程序拦截已标注不确定度主题但无完整条款依据、无效状态或无效日期的B3导出。只有核实有效且适用的依据可进入此块；状态未明时继续检索，不编造条款。程序检查仅验证所提交信息的完整性，不能证明原文、有效性声明或适用性真实；执行智能体仍须核对原件和官方目录。

批注只引用必要短摘录，附原件定位；可从同一原件引用多个条款。不默认U/MPE≤1/3、保护带或CMC是所有用途的通用门槛。直接比较与补充含U核查分别写明，不因补充核查未通过就将设备标为超差。真实测量值超限只提示，不自动删除或要求改成合格数值。

升级仅涉及共用批注契约及B3适配层；证书自身、器具性能、方法用途继续保持既有维度及独立记录，方案编制不消费此信息修改限值。旧记录兼容，原件和历史PDF不重写；重导出另存新副本。无需处理的U信息不制造问题或空批注PDF。
