# 报告工作台 · 0.4.2

## 使用顺序

1. 选择实验室、年度和批次。
2. 点击“接入校准方案”导入XLSX。系统显示七列参数和自动分类的候选设备分组；缺项为“-”。分组卡片与搜索只用于浏览，不需要勾选参数。
3. 点击“导入报告”，可同时选择多份PDF。每批最多50份、单文件30MB；后台同时处理2份。每份依次留存原件、逐页识别、匹配设备并生成基础诊断。一份失败不会阻断其他报告。
4. 在左侧翻页、缩放原页；右侧查看报告信息和匹配依据；诊断报告位于原页区下方。点击字段或对照条目的页码可定位原页。识别时在当前处理页显示扫描线；点击诊断也显示扫描状态，结束后短暂保留完成反馈，不代表技术通过。
5. 多个设备无法区分或身份冲突时，点击“澄清对应关系”，填写实际操作人和选择依据。名称唯一但缺少编号、型号证据时显示“名称候选关联”，仍需确认具体实物。
6. 点击带播放箭头的“开始诊断”按钮，系统匹配方案设备并刷新下方诊断报告。每项以“方案／校准或检定证书信息”双列并排显示，条目顶部给出符合、不符合、待确定或不适用；可筛选设备信息、参数与结果、溯源与依据。日常使用不需要填写核验人或复核表单。
7. 同一候选设备的多份报告可联合审查；系统只合并相同设备引用的报告，不合并其他设备或不同提取版本的同一证书。候选名称关联下的联合审查仍不能证明属于同一实物。
8. 使用“导出批注副本”生成原页批注PDF与审查记录。原证书及其数字签署证据保持留存。

报告列表折叠在“本批次报告”中；总量统计保留在中控台。证书页面不再放置四项统计仪表台，也不展示“审查记录”模块、“登记核验”和“补充问题”功能。校准和检定按各自规则处理。

## 文件入口

```text
data/laboratories/LAB_ID/
  objects/                         实验室规范原件对象库
  campaigns/年度/CAM_ID/
    校准方案/原文件名__WB_ID/
      原件.xlsx                    只读原件副本
      提取记录.json                固定单元格与七列候选
      设备分类__摘要.json           候选设备及参数行引用
    证书报告/
      原件档案/SRC_ID/
        原件.pdf                   识别前留存
        原件索引.json
      设备关联/设备引用/SRC_ID/      唯一身份关联或操作人明确的归属
      待确认关联/设备引用/SRC_ID/    仅名称候选关联
      待匹配/未确定设备/SRC_ID/      未匹配、歧义或冲突
  exports/RUN_ID/                  原页批注副本与固定审查记录
```

设备关联目录内只保存固定关联记录和原件入口，不复制为新的可编辑原件或限值来源。重新关联保留旧索引供追溯，工作台显示数据库最新关联。不要直接改写这些文件。年度调整移动完整批次目录，不改变证书日期、原件摘要或方案版本。

服务重启后，未完成导入显示“已中断”；重新接入同一原件可继续处理，原件和相同提取版本复用。解析失败时已留存的有效PDF原件仍可在本批次重新读取；扩展名伪装等未接入对象库的文件保留在上传暂存区，不视作有效报告。

## 匹配与结论边界

| 情形 | 工作台行为 |
| --- | --- |
| 编号唯一相符，其他已提供身份无冲突 | 自动关联，设备实际对应仍待原页核验 |
| 型号和名称唯一相符，已提供编号无冲突 | 自动关联，缺失身份仍待核实 |
| 只有名称线索且唯一 | 候选归类，保留具体设备待确认 |
| 多台候选相同、字段冲突、未识别身份 | 集中显示候选与理由，待澄清 |
| 用户明确资料归属 | 记录操作人、依据和历史关联；不记作方案确认 |

只有已经结构化、明确确认、当前有效且加入本批次的方案固定基准，才可自动用于覆盖／结果比较。候选Excel的自然语言MPE与不确定度要求不直接生成可执行判据。当前实际工作簿仍未技术确认。

右侧六类诊断分别允许符合、不符合、待核实、不适用。自动文字、OCR与规则得到的是候选；提取不到不等于原件缺项。准确性需要实际设备等交叉证据；溯源性要结合具体项目和活动日期的官方范围及标准器证据；标准适用性和不确定度适用性缺少依据时保留待核实。没有确认基准时，覆盖与结果符合性不作技术通过结论。

当前独立模型服务、官方范围自动下载和任意复杂结果表语义解析尚未接通。项目智能体辅助入口在“固定基准及审查范围”内，可继续接入带原页位置的候选结果。这次的自动化指本地接入、识别、匹配和基础审查流程，不是无人复核的完整专业验收。

## 双列对照的数据边界

对照报告绑定方案提取／基准的具体摘要及证书提取摘要，不建立第二套可编辑限值。候选方案可预对照：左列保留参数、原文点位、MPE及不确定度要求，右列显示已经对应的测量结果或明确标注的相关原文线索。相似文字仅帮助定位，不作为项目已覆盖或数字合格的证据。证书未对应到某项时保持待确定，不直接认定漏项。

实际存在确认基准和足够的对应结果时，逐参数结论沿用既有覆盖及判定规则；信息不足时为待确定。当前原件和候选方案状态不因删除人工界面而改变。比较视图为只读投影，个人工作台隐藏审查记录，后台仍保留固定版本数据供文件完整性与导出使用。

## 紧凑界面与诊断反馈

全局采用Windows XP / Luna风格，标题栏、导航、按钮、表格、弹窗和状态栏使用同一组样式。原页默认整页预览，也可切换适合宽度或放大；识别值与原页页码横向排列。诊断项目保留双列与结论，详细说明展开查看，原文页码在对应内容右侧。点击开始诊断或联合诊断会显示原页扫描与绿色活动块，后端完成即更新结果，再短暂显示完成扫光；不人为延迟结果，也不将动效当成技术核验。减少动态效果的系统设置下使用静态状态提示。

扫描状态验证：`node --test tests/web/scan.test.cjs`。


## 逐点对照与资料空间（0.5.0）

实验室选择只显示实际工作空间。历史迁移与待归属样本保留原目录和原件，在“历史与待归属资料”中只读查看、下载；不参与当前批次设备匹配。显式分类保存在各库 `meta.workspace_role`，CLI 使用 `./labcal lab classify-storage --id ID --role ROLE --reason 说明`，不会改写实验室技术配置。

校准方案默认显示“逐点明细”，也可切回七列设备参数清单。明确点列拆成独立行，传感器容量、标距、计算说明不当作校准点。范围、百分比容量和无法可靠拆分的复杂条件保留原文并提示。

证书的“测量结果明细”显示参数、工况、点位和结果；诊断默认以同一行呈现方案点和证书点，可筛选参数、点位、需要关注、证书独有点等。默认紧凑对照，完整数据列分别列出实测值、误差、重复性、MPE 和不确定度。展开逐点对照可暂时收起原页区；点击页码返回对应原页结果行，无法可靠定位到行时定位整张表。

解析层读取固定提取快照中的表格；文字表格和可辨识表头支持自动结构化，复杂扫描版或未形成表格的内容保留提示，不猜造结果。温度上下偏差、波动度和均匀度分别列项，表级不确定度注明其适用性待核对。方案传感器与报告压力／拉力不能唯一对应时并列候选，不能算作已覆盖。

`point-matrix.v1` 是可重建的只读投影，包括输入摘要、原页证据与对应状态；技术结论仍由固定确认基准和证据规则决定。候选方案、多种限值表述以及未经原页核验的结果不会自动变成“符合”。来源 MPE 与方案 MPE 不同只是差异提示，不直接推导测量结果不合格。

“数据与文件”查询真实数据库、批次目录与文件存在性，展示模块关联、SQLite 快速检查、外键检查和查询耗时。需要完整摘要与业务引用检查时使用 `./labcal doctor --lab ID`。设备台账和机构范围资料入口先展示已保存记录，再接入新资料；空台账不会以方案候选分组冒充实际设备。


## 本机启动与可调工作区（0.5.1）

使用桌面“校准证书工作台.command”或 `./labcal open`。启动器检查本机健康接口与工程标识，只复用当前工程服务；端口被其他应用占用时提示错误，保留其他服务。后台进程与启动终端分离，日志保存于 `data/runtime/workbench.log`。`./labcal open --no-browser` 可只启动服务。更换工程目录后，从新目录执行 `./labcal install-desktop` 更新入口。

工作台采用左侧原页、右上识别信息、右下诊断结果布局。中间竖向分隔条调整左右宽度，右侧横向分隔条调整上下高度；窄窗口下可滚动各区域。表头右边缘拖动调整单列，双击表头分隔线或点“恢复列宽”恢复默认；键盘左右箭头每次调整10像素，Shift每次40像素。

`web/columns.js` 管理报告基本信息、测量明细和诊断表格的显示列宽。紧凑列与完整列分别记忆；`web/panes.js` 管理三块区域比例。显示偏好保存在当前浏览器本机存储，未写入实验室参数或限值。重新打开时优先返回上次实验室、批次、模块和已打开报告；原页链接在固定工作区中定位，保持工具栏可见。
