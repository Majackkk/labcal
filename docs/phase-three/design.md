# 第三阶段设计：实验室中控台与业务闭环

## 本次建设边界

先完成多实验室、多年度、多批次的组织结构，接入用户提供的 Excel 候选方案，再把方案版本、固定基准、证书与审查任务纳入同一工作上下文。原有两阶段事实保留，既有 CLI 继续可用。周期、趋势和异常影响仍未启用。

系统是本地独立应用：一个统一入口、一个本地服务、一套界面；核心应用服务同时供 CLI、界面和项目智能体调用。远程部署、账号体系和自动技术批准不属于本次建设。

## 信息层级

```text
中控台
  实验室（独立业务数据库和原件库）
    年度（导航与归档标签，可待定）
      校准批次（稳定 CAM 标识，同年可多次，跨年可独立命名）
        方案原件 / 候选方案版本 / 固定基准
        证书提取版本 / 审查任务 / 导出记录
    设备台账（跨年度连续存在，配置单独版本化）
```

年度是业务归属标签，不从文件修改时间、上传日期或文件名推定。不清楚时归入 `undated`。校准活动日期、签发日期仍保留各自事实，不被年度标签改写。年度重归档只改变组织信息，不改变技术快照。

设备不是年度文件夹中的重复台账。一个方案可涉及设备组，Excel 分组与设备资产不是同一个概念；接入时先保存原始分组，待明确设备对应关系后再生成正式结构化候选版本。

## 文件与事实分工

```text
data/
  references/                         允许共用的标准与机构参考资料
  laboratories/<LAB_ID>/
    lab.sqlite                        唯一业务事实源
    objects/<摘要>.<扩展名>             原件及可校验的文件对象
    campaigns/<年度或undated>/<CAM_ID>/
      index.json                      从数据库生成的只读资料索引
      README.md                       批次入口说明
      校准方案/<原文件名>__<WB_ID>/     只读原件副本、提取快照与归属索引
    runs/                             固定解析、智能审查包和运行产物
    exports/                          固定版本的文档与批注副本
```

批次目录保存索引，方案导入目录保存只读原件副本与固定提取记录，不维护另一份可编辑参数限值。索引记录相对路径与固定摘要，供人工找文件；应用读取数据库并校验对象。备份包含数据库、对象与批次目录。下载文件由注册对象及运行清单解析，不接受任意路径。

## 新模块与依赖

| 模块 | 职责 |
| --- | --- |
| domain/campaign_contracts.py | 批次与固定对象引用契约 |
| application/campaigns.py | 批次创建、年度归档、对象归属、过滤与索引投影 |
| adapters/spreadsheet.py | 只读 XLSX 单元格、合并、公式及缓存值；不运行公式或外链 |
| application/workbooks.py | 原件接入、固定提取、可配置列映射、候选分组及转方案 |
| application/intelligence.py | 固定审查上下文包、模型候选结果接入；复用已有问题与证据契约 |
| adapters/server.py | 限本机 API，执行实验室及批次边界检查 |
| web/ | 中控台、批次导航、资料清单、方案版本与证书审查 |

不改变原证书、方案、基准快照格式来塞入可变的批次标签。新增关系表保存归属；方案引用必须指定修订号，证书引用必须指定提取版本。技术计算仍消费原有固定基准和实际核验记录。

## 关键流程

1. 新建或选择实验室和批次，再上传资料。上传前显示当前上下文。
2. Excel 原件按摘要留存，逐工作表提取并保留单元格地址。列映射是明确输入或标题候选匹配；歧义留待选择。
3. 原始方案行只保存原文、组别和来源。限值、规范摘录及设备配置均不因接入而获确认。
4. 为指定实际设备整理候选要求，保存新的方案版本。在界面核对结构与就绪问题；实际确认需要明确确认人、确认声明及精确版本。
5. 确认后编译固定基准。证书只能在当前批次中选择；跨批次复用方案需明确“引用已有版本”。
6. 智能体读取固定审查包，输出带原页位置的候选发现。接入校验实验室、批次、证书提取和上下文摘要。原件中的文本不构成执行指令。
7. 程序执行确定性计算，人员核验与复核。更正证书或修改方案产生新版本及新任务，历史可回看。

## 界面与规模

工作台按最新用户要求采用Windows XP / Luna风格，使用紧凑列表和来源在右的布局。左侧选择实验室、年度、批次及工作模块；首页展示实验室和批次概览，默认不铺开所有证书。进入批次后分别展示方案资料与证书审查。清单提供搜索、分页和明确总数；更换上下文清空已选择证书、预览、基准及旧任务状态。

已有未归属资料显示为“未归档资料”，不猜测实际年度，也不自动把样本划给某个实际实验室。用户可将具体固定版本加入批次。旧 CLI 无批次参数仍可查历史；新工作台写入业务必须明确选定批次。

## 智能审查边界

项目智能体可立即使用固定上下文包和结构化结果接入。独立模型服务通过适配层接入，未配置时界面明确显示“项目智能体辅助”，不得显示模型已运行。模型候选数字与实际核验事实分开；模型输出无权新增确认人、批准结论、修改限值或更改原件。

机构能力先支持对应官方附件和有效时间。没有附件或复杂 CMC 未完成核验时维持待核实。补充建议单列，不静默改动确认方案。

## 验证与交付

- 两实验室同名批次隔离；同实验室跨年度、同年多批次独立。
- 切换上下文不显示或提交上一批次的证书、方案与任务；请求绕过界面也被拒绝。
- 原件重复接入幂等；公式、合并标题与重复序号保留；不从分组名虚构资产编号。
- 方案修订和基准固定引用；跨批次引用是显式操作；确认与基准前置条件沿用原有服务。
- 旧资料、备份恢复、证书批注链继续有效；源文件摘要不变。
- 实际 Excel 保持候选；真实确认、核验与技术批准均不代填。

交付分别报告工程能力、原件缺口及业务确认状态。实际模型服务、真实检定样本与真实方案确认的缺口明确列出。
