# 实验室校准中控台

版本0.6.1。先选择实验室，再选择年度与批次，进入方案或证书模块。当前应用在本机运行，通过 `./labcal serve --port 8765` 启动。

## 年度与批次

实验室有独立数据库、原件和输出。设备台账持续存在，年度下可以有多个校准批次；名称、年度和工作状态均可调整，稳定标识不变。年度不明确时留空，进入“年度待定”。年度是业务归属，与证书的实施日期、签发日期分别管理。

新实验室的类型与适用准则可以先保留待明确。在“实验室设置”中由实际操作人员记录明确选择；不支持的专项准则不自动开展用途判定。

```bash
./labcal lab add --id LAB_EXAMPLE --name '示例实验室' --type unresolved --profile unresolved
./labcal campaign add --lab LAB_EXAMPLE --name '年度校准' --year 2026
./labcal campaign list --lab LAB_EXAMPLE
```

年度批次的文件入口位于 `data/laboratories/<LAB_ID>/campaigns/<年度或undated>/<CAM_ID>/`。其中 `index.json`、`README.md`是数据库生成的只读索引。实验室对象库留存原始字节；方案导入文件夹另存只读原件副本及提取快照。年度调整会移动完整批次目录，技术快照保持不变。使用中控台维护资料，不直接改索引或数据库。

归档批次可继续查看，追加前在“批次信息与归档”恢复为进行中。与归属有关的变更保留事件记录。该本地记录不等于联网身份认证。

## Excel方案接入

在当前批次点击“接入校准方案”，选择XLSX。系统保留原件、工作表、单元格、合并标题、公式与缓存值；不计算公式或访问外部工作表。公式缓存值保持候选。原文中的设备组、规范摘录及限值不会自动成为实际设备配置或确认基准。

“设备与校准参数清单”自动填入七列：设备名称、厂家、设备型号、设备编号、校准/检定参数、允许误差 MPE 要求、不确定度要求。缺失或未明确的字段显示`-`，底层保存为空值。支持明确列标题、标注身份信息和设备身份单元格的纵向合并；不把行序号当作设备编号，不从未标注的型号样式字符串猜填身份。点位、工况、依据和单元格位置仍可在“原文与位置”中回看。明确写出的不确定度要求可从原文提取，引用的含义与适用性保持待核验。

每次导入会建立`校准方案/<原文件名>__<WB_ID>/`，保存`原件.xlsx`、`提取记录.json`、`索引.json`和`README.md`。原件副本及固定JSON只读；重复导入相同内容及解析版本复用目录，摘要冲突时拒绝覆盖。导入完成后自动打开七列表格，可展开“导入文件夹位置”查看实际路径。同一原件的新解析保留旧快照，列表默认展示最新提取，可展开历史提取查看。

导入后自动按明确设备身份、工作表和原文分组建立候选设备索引，汇集其全部参数行。日常界面不需要勾选参数或手工建立设备候选稿；选择设备卡片或分组只用于浏览。没有身份信息的组合设备、辅助设备组仍保持候选分组，不能当作已区分的具体实物。身份不清或多个候选时集中澄清对应关系。导入目录追加带摘要的只读设备分类索引。

```bash
./labcal workbook add --lab LAB_EXAMPLE --campaign CAM_ID --file /绝对路径/方案.xlsx
./labcal workbook show --lab LAB_EXAMPLE --id WB_ID
./labcal report catalog --lab LAB_EXAMPLE --campaign CAM_ID
```

不同表格可通过`workbook add --mapping 文件.json`明确列映射。映射按工作表名组织，`header_row`为表头行号，其他值为从1开始的列号。例如：

```json
{"工作表名":{"header_row":1,"equipment_name":1,"manufacturer":2,"model":3,"equipment_number":4,"parameter":5,"limit":6,"uncertainty":7}}
```

自动标题匹配仅产生候选整理；不能匹配的工作表仍保留原始单元格，需明确映射后重新接入。每个映射产生固定提取版本，不覆盖旧版本。当前界面的分组参数视图按每页8行展示，证书与引用清单按每页20项展示。

## 方案版本与固定基准

在“设备方案版本”查看具体修订及覆盖、判定就绪问题。参数编辑器支持单位、点位、范围、报告字段、实施方式和原表要求的依据性质。复杂组件、工况、限值、不确定度和判据可在完整结构中整理，或通过项目智能体和CLI接入。界面不会从自然语言限值直接猜出可执行规则。

保存会建立新候选版本，原版本保留；界面拒绝从已被更新的旧版本直接覆盖保存。“与上一版本比较”列出参数新增、移除和变化。规范或制造商主张仍需相应原件和实际核验，工作簿的摘录不替代原件。

“确认这个具体版本”需填写实际确认人、明确声明并核对设备配置、方案用途及参数要求。未达到覆盖就绪条件时不能确认。实际确认后才可生成固定验收基准；缺少可执行判据时只可核对覆盖，不能自动判定用途。

## 证书审查与智能体辅助

点击“导入报告”可同时选择多份PDF，后台按原件归档、逐页识别、设备匹配、基础诊断依次处理；每份文件独立成功或失败。左侧预览原页，右侧展示候选信息；点击“开始诊断”后，在下方查看方案／证书双列对照与逐项结论，点击页码定位原页。细节见[报告工作台](report-workbench.md)。批注副本沿用[证书工作台指南](certificate-guide.md)的原页核验、复核与批注副本流程。上传和请求均检查批次归属。切换实验室或批次会清空已选资料与预览。

“固定基准及审查范围”中的“项目智能体辅助”保存固定上下文包，其中包含选定提取版本、已核验事实及可选固定基准。当前为项目智能体辅助，独立模型服务尚未配置；准备审查包不表示已运行模型。项目智能体读取原页后返回候选字段、结果和带位置的问题，界面可接入其JSON结果。

```bash
./labcal intelligence prepare --lab LAB_EXAMPLE --campaign CAM_ID --extractions EXT_ID
./labcal intelligence show --lab LAB_EXAMPLE --id INT_ID
./labcal intelligence import --lab LAB_EXAMPLE --campaign CAM_ID --record 候选结果.json
./labcal intelligence list --lab LAB_EXAMPLE --campaign CAM_ID
```

审查包及结果模板保存在实验室 `runs/INT_ID/`。结果绑定包摘要、批次和提取摘要。候选字段、数字保存于独立候选结果表，不进入实际核验表；候选问题进入待核实通道。点击“查看原页”定位候选结果；个人界面不提供核验登记表单。复杂结果通过结构化资料入口保留全部上下文，不自动代填人员或提升候选事实。

机构范围仍先接入官方附件并核对有效时间。复杂CMC及其他溯源路线未充分核验时保持待核实。

## 旧资料与复用

旧方案、样本和任务保留原实验室归属，不推定年度或转入新的实际实验室。中控台显示未归档数量。在当前批次点击“引用已有资料”，按名称检索本实验室的具体原件、方案、证书提取、基准或审查任务，明确加入批次。引用审查任务时同时引用其关联证书，供原页回看；不会自动把历史基准设为当前审查基准。

CLI仍允许按实验室查询旧记录；HTTP业务读写要求批次上下文。批次组织不是账号权限系统，未来联网部署仍需单独的身份与权限层。周期、趋势及异常影响继续预留。

## 实际资料接入

工作簿须按用户明确指定的实验室、年度及批次接入并保留原件。识别分组和候选参数的数量以具体工作簿为准，不是程序或模板的默认值；接入不补造实际设备、确认人、原页核验人、验收基准或技术批准。

## 数据与文件完整校验

左侧“数据与文件”可查看菜单对应的数据库与真实目录；“完整校验文件与版本”只读核对原件摘要、固定记录、批次归档及导出。过期索引与原件损坏分开显示。结构及长期边界见[功能对应表](structure-and-function-map.md)。OCR选择见[本地OCR说明](local-ocr.md)。
